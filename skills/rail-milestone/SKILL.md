# rail-milestone — step 표와 실행

차례, 표의 꼴, 묻는 문구, 작업자 띄우기·닫기, 커밋 관문은 `status` 의 "다음 할 일"이 그때그때 알려 준다. 여기는 그 안에서 네가 판단할 것이다. 작업자 지시서는 `workers.md` 를 따른다.

## step 표 나누는 법
- 현재 마일스톤만 나눈다(사람이 미리 승인할 때만 다음 2~3개까지). 제품 코드는 step 으로만 만든다.
- 기본은 기능 목록이다: 줄 하나가 사용자가 알아볼 기능 하나이고, 작업자 하나가 시험과 구현을 함께 한다. 위험한 모듈(데이터 저장, 외부 입력 표시, 보안)은 완료 기준에 경계 값과 빈 데이터를 적어 확인 작업자가 보게 한다.
- 중간 리뷰는 두지 않는다(기능마다 확인 작업자가 본다). 마지막 줄은 마지막 리뷰(Codex 1번)다. 이유: Codex 토큰이 작다.
- 서로 기다릴 필요 없는 일은 "기다리는 step" 칸에 기다릴 것만 적어 동시에 돌린다.
- 완료 기준은 돌릴 명령과 기대 결과로 쓴다. 기획서 성공 장면의 "이어지는 step" 이 가리키는 줄은 그 장면의 자동 확인과 진짜 자료를 완료 기준에 그대로 옮긴다.
