# rail-brief — 브리프 인터뷰

목표: 누가, 언제, 무엇을 하다가, 무엇이 불편한지를 알아내 성공 장면으로 적는다. 묻고 기록하는 차례, BRIEF.md 꼴, 승인 묻기는 `status` 의 "다음 할 일"이 알려 준다.

## 인터뷰하는 법
- 기술 질문(언어, 프레임워크, 데이터베이스, 구조)을 하지 않는다. 이유: 사람은 결과 화면으로 고를 뿐이고, 기술은 뒤의 결정 카드에서 고른다.
- 쉬운 한국어로 묻고, 사람에게 보이는 글에만 예시 답을 한 줄 붙인다(`ask` 에는 질문 한 줄만). "모르겠다"면 그대로 받아 적는다.
- 8개를 다 쓰지 않아도 된다. 장면이 3개 이상 나오면 멈춰도 된다.
- 질문 틀(답에 맞춰 바꾼다): 쓰는 사람과 여는 때 / 지금 하는 방법과 가장 불편한 점 / 열자마자 보고 싶은 화면 / 가장 자주 하는 동작 / 없으면 곤란한 정보나 숫자 / 들어가지 않았으면 하는 것 / 데이터가 있는 곳과 양 / "됐다!" 하고 느끼는 장면.

## 장면 쓰는 법
- 장면은 사람이 직접 해 보고 화면에서 눈으로 확인되는 한 문장("~하면 ~가 보인다")이다.
- 사람이 하지 않은 말을 지어내지 않는다. 이유: 브리프가 사람의 하루가 아니라 AI 의 추측이 된다.
