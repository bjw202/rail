# 레일 사용법 (한 쪽)

레일은 "지금 어디이고 다음에 뭘 할지"를 알려 주고, 단계를 건너뛰면 넘어가지 않게 막는 작은 도구입니다. 상태는 `.rail/state.json` 한 파일에 있고, 막을지는 AI의 기분이 아니라 `.rail/bin/rail.mjs` 스크립트가 판정합니다.

## 명령은 하나
- `/rail` — "다음 뭐 해?" 거의 모든 순간에 이것만 칩니다.
- 기능을 바꾸고 싶으면 그냥 말하세요. 기획서를 고치고 "살아 있는 세 줄"의 계획 변경에 적습니다. 뭔가 이상하면 그 말을 하세요. 고침 step 을 만듭니다.

## /rail 을 치면
1. 상태 파일을 읽고 세 줄을 보여 줍니다: 위치 / 기다리는 것 / 다음 할 일.
2. 빠진 것이 있으면 "다음 할 일"이 그것부터 채우라고 알려 줍니다. 관문은 단계 순서를 보고, 마일스톤을 시작할 때 착수 전 결정·시험이 풀렸는지, 닫을 때 모든 step ✅ 와 사람의 장면 판정까지 봅니다.
3. AI가 할 일이면 AI가 하고, 사람 일이면 질문 하나만 합니다.

순서는 기획(인터뷰로 기획서 `docs/PLAN.md` 한 장) → 착수 전 결정과 가정 시험 → 마일스톤(step 표대로 만들기) → 장면 확인(직접 해 보기)이고, 마일스톤마다 뒤의 세 단계를 되풀이합니다.

## 사람이 하는 일 (이것뿐입니다)
- 레일이 보여 주는 화면·예시에 반응하고, 실제 파일로 평소 하던 일을 한 번 해 보이기. 가정마다 "깨지면 얼마나 아픈가"만 답하기.
- 기획서(맨 위 네 줄, 성공 장면, 첫날 실패 장면, 마일스톤 지도)에 "맞음" 또는 고칠 문장 말하기. 이것이 승인입니다.
- 착수 전 결정에서 후보 하나 고르기("B"만, "추천대로"도 됩니다). 가정 시험 결과의 감수할 점을 받아들일지 답하기. "미룸"·"판단 보류"는 기한이 있어야 하고, 기한이 지나면 다시 묻습니다.
- 기능 목록(step 표)이 나오면 "시작"이라고 말하기(자율 모드면 묻지 않습니다). 밤새 맡길 때는 다음 마일스톤 2~3개의 기능 목록을 한꺼번에 승인할 수 있습니다(`plan approve`).
- 마일스톤 끝에 리허설 결과(스크린샷과 통과 수)를 보고, 됨/안 됨과 본 것 한 줄 남기기. 자율 모드로 넘어간 마일스톤은 "장면 판정 대기"에 남아 있으니 돌아와서 차례로 답합니다.
- 커밋 정책(커밋마다 묻기 / 묻지 않고 로컬 커밋), 자율 모드 켜고 끄기, 부품 하나 꺼 보기, 작업자마다 worktree 쓰기(`isolation`)는 리더 세션에 직접 말할 때만 바뀝니다. 남이 전한 말로는 바뀌지 않습니다.

## 관문에 막혔을 때
`[관문] ... 로 갈 수 없습니다. 빠진 것: ...` 과 `돌아갈 단계` 가 나옵니다. 빠진 것을 채우면 됩니다. 관문을 피하려고 `state.json` 을 손으로 고치지 마세요. 레일이 틀렸다고 느끼면 그 말을 하세요. `rail_edit` 로 기록하고 고칩니다.

## 자율 모드
`.rail/config.json` 의 `autonomy.mode` 가 `on` 이고 커밋 정책이 `auto-local` 이면, 리더는 턴마다 `next` 를 불러 멈춤 규칙(done, human, busy, same_failure, budget, off)을 봅니다. Orca 자동화는 `next --precheck` 의 종료 코드(할 일 있음 0, done 10, human 11, budget 12, same_failure 13, busy 14, error 15, off 16)를 보고 리더를 깨웁니다. 예산 규칙은 `autonomy.budget.costCommand` 가 비용을 잴 때만 쓰고, 비어 있으면 `status` 에 경고 한 줄만 냅니다.

## 파일
`docs/PLAN.md`(기획서, 틀은 `.rail/plan/template.md`), `docs/plan/refs/`(참고 서랍), `docs/plan/Mx.md`(지금 마일스톤의 step 표), `docs/decisions/D-xx.md`(시제품 카드), `.rail/trial/`(가정 시험 틀과 버리는 코드), `.rail/state.json`(위치), `.rail/config.json`(검사 명령, 커밋 정책, 자율 모드와 예산, 보험 부품과 꺼 둔 부품), `.rail/test-baseline.json`(잠긴 시험 파일 목록), `.rail/review/`, `.rail/rehearsal/Mx/`(리허설 결과와 스크린샷), `.rail/check/`(확인 지시서 틀과 결과), `.rail/stale/`(낡은 시험 판정), `.rail/proto/`(시제품), `.rail/reference/Mx/`(기준 화면), `.rail/log.jsonl`(사건 기록 — 레일의 효과를 재는 자료).

## 훅
세션을 열 때 위치 세 줄 보여 주기, 이미 있는 시험 파일과 `fixtures/` 고치기 막기(우회는 `RAIL_ALLOW_TEST_EDIT=1` 을 붙여 Claude 를 띄우기), 멈추기 전 마무리 검사(`checkCommand` 가 비면 건너뜀), 압축 직전 요약 지시와 압축 직후 이어받기 안내.

## 검사 명령 쓰기
`checkCommand`, `verify` 의 `command`, `autonomy.budget.costCommand` 는 셸에서 돕니다. Windows 에서는 cmd.exe 라 작은따옴표가 따옴표로 먹지 않으니, 따옴표는 큰따옴표로 쓰세요(JSON 안에서는 `\"`).
