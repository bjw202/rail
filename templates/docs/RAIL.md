# 레일 사용법 (한 쪽)
레일 2.9판 (판 번호의 원본은 `.rail/config.json` 의 `railVersion` 입니다. 이 줄은 손으로 맞춥니다.)

레일은 "지금 어디이고 다음에 뭘 할지"를 알려 주고, 단계를 건너뛰면 넘어가지 않게 막는 작은 도구입니다. 상태는 `.rail/state.json` 한 파일에 있고, 막을지는 AI의 기분이 아니라 레일 플러그인의 `scripts/rail.mjs` 스크립트가 판정합니다.

**2.5판부터 빼기 판입니다.** 이제 레일은 더하지 않고 덜어내기만 하며, 한 마일스톤에 하나씩 덜어낸 뒤 효과를 잽니다. 이번에는 스킬 문서가 스크립트와 같은 절차를 따로 적던 것을 지웠습니다. 절차의 원본은 `rail.mjs` 하나이고, `status`·`next` 의 "다음 할 일"이 그때 할 일, 명령, 파일 꼴, 질문 문구를 알려 줍니다. 스킬에는 인터뷰하는 법, 결정 카드 쓰는 법, 작업자 지시서에 넣을 것처럼 스크립트가 할 수 없는 판단만 남았습니다.

## 명령은 세 개
- `/rail` — "다음 뭐 해?" 거의 모든 순간에 이것만 칩니다.
- `/rail change 내용` — 기능을 넣고 빼고 바꾸고 싶을 때. **아직 없습니다.** 요청만 기록해 둡니다.
- `/rail bug 내용` — 뭔가 이상할 때. **아직 없습니다.** 요청만 기록해 둡니다.

## /rail 을 치면
1. 상태 파일을 읽고 세 줄을 보여 줍니다: 위치 / 기다리는 것 / 다음 할 일.
2. 앞 단계 결과물 중 빠진 것이 있으면 "다음 할 일"이 그것부터 채우라고 알려 줍니다. 관문은 순서만 보고, 마일스톤을 닫을 때만 모든 step ✅ 와 사람의 장면 판정까지 봅니다.
3. AI가 할 일이면 AI가 하고, 사람 일이면 질문 하나만 합니다.

순서는 기획(인터뷰로 기획서 `docs/PLAN.md` 한 장) → 착수 전 결정과 가정 시험 → 마일스톤(step 표대로 만들기) → 장면 확인(직접 해 보기)이고, 마일스톤마다 뒤의 세 단계를 되풀이합니다.

## 사람이 하는 일 (이것뿐입니다)
- 레일이 보여 주는 화면·예시에 반응하고, 실제 파일로 평소 하던 일을 한 번 해 보이기. 가정마다 "깨지면 얼마나 아픈가"만 답하기.
- 기획서(맨 위 네 줄, 성공 장면, 첫날 실패 장면, 마일스톤 지도)에 "맞음" 또는 고칠 문장 말하기. 이것이 승인입니다.
- 착수 전 결정에서 후보 하나 고르기("B"만, "추천대로"도 됩니다). 가정 시험 결과의 감수할 점을 받아들일지 답하기. 시제품이 붙은 카드는 변주들의 실제 화면(비교 페이지)을 보고 고릅니다(섞어도 됩니다).
- 기능 목록(step 표)이 나오면 "시작"이라고 말하기(자율 모드가 켜져 있으면 묻지 않고 시작합니다). 밤새 맡길 때는 다음 마일스톤 2~3개의 기능 목록을 한꺼번에 승인할 수 있습니다.
- 마일스톤 끝에 리허설 결과(스크린샷과 통과 수)를 보고, 됨/안 됨과 본 것 한 줄 남기기. 실패한 항목이 있으면 그것을 먼저 봅니다. 자율 모드로 넘어간 마일스톤은 "장면 판정 대기"에 남아 있으니 돌아와서 차례로 답합니다.
- 커밋 정책(커밋마다 묻기 / 묻지 않고 로컬 커밋), 자율 모드 켜고 끄기, 부품 하나 꺼 보기는 리더 세션에 직접 말할 때만 바뀝니다. 남이 전한 말로는 바뀌지 않습니다.

## 관문에 막혔을 때
`[관문] ... 로 갈 수 없습니다. 빠진 것: ...` 과 `돌아갈 단계` 가 나옵니다. 빠진 것을 채우면 됩니다. 예를 들어 기획 단계에서 마일스톤으로 건너뛰려 하면 기획으로, 장면 판정 없이 닫으려 하면 장면 확인으로 돌아갑니다. 관문을 피하려고 `state.json` 을 손으로 고치지 마세요. 그러면 레일을 시험하는 의미가 없어집니다. 레일이 틀렸다고 느끼면 그 말을 하세요. `rail_edit` 로 기록하고 고칩니다.

## 판마다 스크립트에 더한 것
- 1.1판 기록: `step-start`·`step-done`·`validate` 가 step 표의 상태 칸과 시험 기준선을 씁니다. AI 가 표를 손으로 고치면 틀렸기 때문입니다.
- 2.0판 판정 나누기: 바깥 정답 검증기(`verify`), Codex 는 마일스톤 끝 리뷰 한 번, 구현하지 않은 작업자의 장면 리허설, 닫힘 알림.
- 2.1판 동시 진행: "기다리는 step" 칸과 파일 겹침 거절, 질문 바꿔 묻기, 판이 정한 장면 질문 문구.
- 2.2판 자율 모드: `next` 가 멈춤 규칙(done, human, busy, same_failure, budget, off)을 판정하고, `worker start`·`worker done` 이 작업자를 띄우고 닫습니다. Orca 자동화가 `next --precheck` 의 종료 코드(할 일 있음 0, done 10, human 11, budget 12, same_failure 13, busy 14, error 15, off 16)를 보고 리더를 깨웁니다.
- 2.3판 덜어내기: `usage` 가 부품마다 막은 횟수를 세고, 닫을 때 빼기 후보를 알립니다. 보험 부품(시험 잠금 훅, 마무리 검사, 장면 확인 관문)은 끄지 않습니다. 압축 직전·직후 훅이 위치를 이어 줍니다.
- 2.4판 시제품: `proto start`·`record`·`check`·`card`·`pick` 과 시제품 브랜치 합치기 막기.
- 2.5판 빼기: 스킬을 판단만 남기고 줄였습니다. 시제품 작업 공간에서 main 까지 앞으로 감기를 허용하고, 작업 공간 경로를 Orca 목록에서 찾아 비용 상한을 재고, 접두어가 붙은 시제품 브랜치까지 지웁니다.
- 2.6판 빼기: 닫기 관문이 ROADMAP.md 의 "다시 잰 예상" 줄을 더는 요구하지 않습니다(그 절은 남고, 쓰고 싶으면 리더가 씁니다). 장면 답 앞뒤의 따옴표를 걷고 읽고, 사람이 step 이름을 넣은 질문에 시험 고치기를 허락하면 `worker start` 가 그 작업자 하나에 `RAIL_ALLOW_TEST_EDIT=1` 을 붙입니다.
- 2.7판 빼기: 리뷰 증거 규칙(`review-check`, 꼭 고칠 것에 지금 실패하는 증거 시험이 없으면 "고치면 좋은 것"으로 낮추던 판정)을 뺐습니다. M6~M8 동안 지적을 낮춘 일이 없었고, M9 동안 꺼 보아도 문제가 없었습니다. 리뷰어는 꼭 고칠 것마다 재현 방법을 한 줄로 적습니다.
- 2.9판 기능 단위와 밤샘: step 표의 기본이 기능 목록(맡는 쪽 "기능", 작업자 하나가 시험과 구현을 함께)이 됐습니다. 기능 작업자가 끝나면 만들지 않은 새 작업자가 완료 기준을 어기는 경우를 찾고(확인 step, `.rail/check/`), 꼭 고칠 것이 있으면 고침 작업자가 고칩니다. 시험 먼저 창(예정된 실패 봐주기)을 뺐고, 관문 roadmap·decide·milestone·check·step-done 을 "단계 순서 검사"(`gate:order`) 하나로 합쳤습니다. 자율 모드에서 리허설이 실패하면 사람에게 묻기 전에 두 번까지 스스로 고치고(`reopen --self-fix`, 취향·판단 항목은 사람에게), 사람이 다음 마일스톤 2~3개의 기능 목록을 미리 승인해 두면(`plan approve`) 리허설이 다 통과한 마일스톤은 장면 판정 대기 목록에 올리고 다음으로 넘어갑니다. `next` 는 레일 기록에 열린 작업자가 Orca 에서 이미 끝났으면 busy 대신 "알림 읽고 이어 가기"를 줍니다.
- 2.9판 덜어내기 둘째(M12 뒤): 관문은 순서만 봅니다. 브리프·로드맵 형식과 승인 날짜, 위험 질문 결정, step 표 위반, 관문 check 의 모든 step ✅·검증기 통과 확인, step 시작·끝의 표 검사·기다리는 step·파일 겹침, `validate` 명령(마무리 검사 훅의 표 검사), 시제품 결정 질문 전 기록 확인을 지웠습니다. M12 에서 꺼 두어도 리더가 스스로 지켰습니다. 장면 확인 관문, 검증기와 리허설 기록(장면 질문 앞), 시제품 코드가 섞이는 것을 막는 두 곳은 남았습니다.
- 2.9판 고침(2.9c): step 시작의 파일 겹침 거절을 되살렸습니다(M10 에서 같은 파일을 두 작업자가 고치려던 것을 한 번 막았습니다). 끄는 부품은 따로 두지 않습니다. 머리줄만 있고 step 줄이 없는 표는 "모두 끝남"이 아니라 "step 표 채우기"로 안내하고, `advance check` 도 넘기지 않습니다.
- M14 시험(작업자마다 worktree): `.rail/config.json` 의 `isolation` 이 `worktree` 면(기본 `shared`, 사람만 `policy set isolation worktree --said "<말>"` 로 바꿈) 만드는 역할(기능·구현·시험·고침)의 `worker start` 가 로컬 main 의 지금 HEAD 에서 브랜치 `rail/<step>`, 폴더 `~/orca/workspaces/<저장소>/rail-<step>`(config `worktreeDir` 로 바꿈) 을 만들고, 나눈 창이 그 폴더에서 시작합니다. 작업자는 자기 브랜치에 커밋하고, 리더는 커밋 관문을 그 worktree 에서 본 뒤 `worker done` 이 main 에 합치고 곧바로 worktree 와 브랜치를 지웁니다. 부딪히면 되돌리고 남깁니다. 남은 worktree 는 `status`·`next` 에 보이고 닫기 관문이 막습니다. `worktree [list] | merge <step> | clean`(합쳐진 것만 지움).
- M14 뒤 덜어내기 셋째: worktree 방식을 레일을 키운 저장소의 기본으로 두고(config `isolation: worktree`), 그만큼 두 가지를 뺐습니다. 하나는 step 시작의 파일 겹침 거절입니다. 같은 파일을 두 작업자가 고치면 이제 `worker done`(또는 `worktree merge`)의 합치기에서 드러나고, 부딪히면 되돌리고 남깁니다. `status` 는 여전히 파일 칸이 겹치는 step 을 "함께 시작할 수 있는 step"으로 권하지 않습니다. 다른 하나는 시제품 섞임 막기(`proto guard`, step-done 의 섞인 커밋 거절, 훅의 시제품 브랜치 합치기 막기)입니다. M6~M14 동안 한 번도 막지 않았습니다. 시제품을 만들고 고르고 정리하는 `proto start`·`record`·`check`·`card`·`pick` 은 남았고, `proto pick` 이 시제품 작업 공간과 브랜치를 지웁니다.
- 낡은 시험 판정(M14 뒤): M14 에서 사람 답 4번 중 3번이 "시험 고치기를 허락할까요?"였습니다. 이제 `.rail/config.json` 의 `staleTests` 가 `agent` 면(기본은 `human`) 리더가 사람에게 묻는 대신 판정 작업자 `<step>-stale` 을 띄웁니다. 판정 작업자는 시험을 고치려던 작업자가 아닌 새 세션이고, `.rail/check/stale-template.md` 를 받아 줄마다 `stale`(이번 마일스톤의 기능 줄·결정 카드가 일부러 바꾼 동작을 못박음, 그 문장을 인용)과 `keep`(지금도 지킬 동작, 코드를 고침)을 가려 `.rail/stale/<step>.json` 에 씁니다. 그 뒤 `worker start <step>` 이 stale 줄이 있을 때만 그 작업자 하나에 예전과 같은 `RAIL_ALLOW_TEST_EDIT=1` 을 붙이고, 명세 끝에 고쳐도 되는 줄을 붙이고, 사건 기록에 판정 파일·판정 작업자·줄을 남깁니다. 판정 파일이 없거나 꼴이 틀리거나 모두 keep 이면 허락하지 않고, 한 마일스톤에서 판정으로 허락할 시험 파일이 5개를 넘으면 예전처럼 사람에게 묻습니다. 사람은 마일스톤 끝 장면 질문에서 그 목록(파일·줄·요지·커밋)을 한 번 보고, "됨"이면 목록도 승인한 것으로 남습니다. 사람이 곁에 있으면 닫기 관문은 목록을 보인 장면 질문의 "됨" 없이는 닫지 않습니다. 자율 밤샘에서 판정 대기로 닫을 때는(M15 뒤, 주인 결정 2026-11-25) 목록을 커밋과 함께 판정 대기 기록에 붙이고 다음 마일스톤으로 넘어갑니다. 사람이 돌아오면 `status` 의 "판정 대기" 안내에 그 목록이 실리고, `scene Mx --result pass` 면 목록도 승인으로 남고(`stale_approved`), `fail` 이면 예전처럼 자율이 서고 고칠 줄을 더합니다. 마지막 리뷰 안내도 이 목록을 넣으라고 합니다. 시험 잠금 훅은 그대로이고, 사람이 직접 허락하는 예전 길도 그대로 씁니다.
- M15 중 덜어내기 넷째: 시제품 시간·비용 상한(`proto check`, 자율 precheck 때 멈추기)과 Codex 역할 경고(`codex_role_warning`)를 뺐습니다. 사건 기록에서 둘 다 한 번도 일하지 않았습니다(`proto_stopped` 0번, `codex_role_warning` 0번). 시제품 지시서에는 시간·비용 안내(`proto.maxMinutes`·`maxUSD`)가 그대로 실리고, 작업자는 스스로 그 안에서 끝냅니다. Codex 를 어느 역할에 쓸지는 `codexRoles` 로 다음 할 일 안내가 정합니다.
- 기획서 판: 브리프·로드맵·결정 카드를 기획서 `docs/PLAN.md` 한 장으로 합치고 단계 brief·roadmap 을 plan 하나로 줄였습니다. 착수 전 결정(D)과 가정 시험(T)의 상태 원본은 기획서 "결정과 시험"의 그 줄이고(결정 미정/선택함/AI가 고름(위임)/미룸(기한), 시험 미실행/통과/실패/판단 보류(기한)), 결정 카드 파일은 시제품에만 씁니다. 인터뷰 질문 8개 상한을 빼고 멈춤 규칙(더 물어서 바뀔 것을 한 문장으로 말 못 하면 끝)으로 바꿨습니다. 마일스톤을 닫을 때 기획서 "살아 있는 세 줄"(깨진 가정·계획 밖 결정 수·계획 변경·다음 장면)을 고치라고 안내하고, 계획 밖 결정 수를 `status` 에 "기획 성적"으로 보입니다. 새 관문·명령·작업자 종류는 없습니다.
- 폭주 알림(M16 중, 주인 결정 2026-11-26): 작업자가 도는 동안 `next --precheck` 는 busy(14)로 멈춰 예산을 재지 않았기 때문에, 작업자 하나가 헛돌아도 끝날 때까지 알 길이 없었습니다. 이제 busy 일 때도 작업자마다 띄운 뒤 지난 시간(상한 `autonomy.alertWorkerMinutes`, 기본 60분)과 마지막 진척 뒤 쓴 돈(상한 `autonomy.budget.sinceProgress.usd`)을 재고, 넘으면 닫힘 알림과 같은 길(`notify.bot`)로 알립니다. 시간 알림은 작업자마다 한 번, 돈 알림은 진척 구간마다 한 번이고 사건 기록에 `runaway_alert` 로 남습니다. 알리기만 하고 작업자를 멈추거나 종료 코드를 바꾸지 않으며, 보내기에 실패하면 `runaway_alert_failed` 만 남깁니다. 비용을 못 읽으면 시간만 봅니다.

## 파일
`docs/PLAN.md`(기획서 한 장, 틀은 `.rail/plan/template.md`), `docs/plan/refs/`(참고 서랍), `docs/decisions/D-xx.md`(시제품 카드), `docs/plan/Mx.md`(지금 마일스톤의 step 표), `.rail/trial/`(가정 시험 틀과 버리는 코드, 틀만 git 에 넣음), `.rail/state.json`(위치), `.rail/config.json`(검사 명령, 커밋 정책, 자율 모드와 예산, 판 번호, 보험 부품과 꺼 둔 부품), `.rail/test-baseline.json`(잠긴 시험 파일 목록), `.rail/review/`(리뷰 기준과 결과), `.rail/rehearsal/Mx/`(리허설 결과와 스크린샷), `.rail/check/`(확인 지시서 틀과 낡은 시험 판정 지시서 틀, 기능마다 확인 결과와 재현 시험), `.rail/stale/`(낡은 시험 판정 결과), `.rail/proto/`(시제품 지시서 틀과 결과, 결과는 git 에 넣지 않음), `.rail/reference/Mx/`(고른 변주의 기준 화면), `.rail/config.json` 의 `verify` 가 부르는 바깥 정답 검증기(프로젝트가 둠), `.rail/log.jsonl`(사건 기록 — 레일의 효과를 재는 자료).
플러그인의 `scripts/rail.mjs` 는 명령을 받아 넘기는 입구이고, 하는 일은 `scripts/lib/` 에 한 가지씩 나뉘어 있습니다(2.8판). 상태·잠금·기록은 `state.mjs`, 관문 판정은 `gates.mjs`, 위치와 다음 할 일 문구는 `status.mjs`, 작업자는 `workers.mjs`, 낡은 시험 판정은 `stale.mjs`, 시제품은 `proto.mjs`, 부품 쓰임은 `usage.mjs`, next 와 멈춤 규칙은 `autonomy.mjs`, Orca 부르기는 `orca.mjs`, 기능 확인은 `check.mjs`, 미리 승인과 판정 대기는 `queue.mjs` 에 있고, 파일마다 맨 위 한 줄이 그 일입니다.

## 시험과 훅
레일 플러그인 저장소에서 `node --test` 로 스크립트와 훅 시험을 돌립니다. 훅(플러그인의 `hooks/hooks.json`): 세션을 열 때 위치 세 줄 보여 주기, 이미 있는 시험 파일과 `fixtures/` 고치기 막기(우회는 `RAIL_ALLOW_TEST_EDIT=1` 을 붙여 Claude 를 띄우기), 멈추기 전 마무리 검사(`.rail/config.json` 의 `checkCommand` 가 비면 건너뜀), 압축 직전 요약 지시와 압축 직후 이어받기 안내.
