## 제한
- 시간 {{minutes}}분, 비용 ${{usd}} 안. 넘을 것 같으면 그때까지 된 것으로 스크린샷을 찍고 끝낸다.
- 시험을 쓰거나 고치지 마라. 레일(`.rail/`, `.claude/`)을 건드리지 마라. `node --test` 통과는 요구하지 않는다(마무리 검사 훅이 붙잡으면 "시제품이라 시험을 돌리지 않음"이라고 보고하고 끝낸다).
- 고칠 파일은 화면을 그리는 곳만. 데이터 읽기 코드는 바꾸지 않고 이미 있는 값을 쓴다. 외부 라이브러리·CDN 금지.
- 커밋은 이 작업 공간의 자기 브랜치에만 한다. 푸시·합치기 금지(레일의 커밋 관문이 시제품 브랜치의 합치기를 막는다).

## 할 일
1. 위 변주대로 화면을 만든다.
2. 앱을 127.0.0.1 의 빈 포트에 띄우고 ego-browser 스킬로 아래 화면을 찍는다. 파일은 이 작업 공간이 아니라 리더의 폴더 `{{dir}}/` 에 아래 이름 그대로 저장한다.
{{shots}}
3. 화면마다 첫 화면이 뜨는 데 걸린 시간을 잰다.
4. 서버를 끄고 브라우저 창을 닫는다.
5. 결과를 `{{result}}` 에 JSON 으로 쓴다. 리더가 `rail.mjs proto record` 로 기록한다(빠진 칸이 있으면 거절된다).
   `{{example}}`
   - shots: 위 폴더 안의 파일 이름. measured: 잰 값(이름: 값). good·bad: 실제 데이터에서 본 좋은 점·거슬린 점 2개씩(예: 긴 이름, 많은 카드, 한 도구가 다른 도구를 누름). minutes: 걸린 분. usd: 모르면 null.
